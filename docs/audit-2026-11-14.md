# Auditoria 2026-11-14 (v0.9.0-beta.1)

Auditoria feita antes da migração para o framework vukem (ver [Migração](#migração-para-o-vukem)). Base: `origin/main` em `266f105`, Go 1.27.4, Windows 11.

## Resumo

- A aplicação funciona: 50 specs e2e web e 4 specs e2e desktop passam; `go vet`, `gofmt` e `golangci-lint` limpos.
- Um teste Go falha em clone limpo (fixture binária ignorada pelo git). É o único bug de testes encontrado.
- Pontos menores de higiene: `go.mod` não está tidy, regra do `AGENTS.md` proibia CI, sem workflow de CI.

## Store (internal/store)

- SQLite via `modernc.org/sqlite`, uma conexão (`SetMaxOpenConns(1)`), pragmas `foreign_keys`, WAL, `busy_timeout`, `synchronous(NORMAL)`.
- Migrações SQL embutidas (`0001_init`, `0002_card_revision`) registradas em `schema_migrations`; backup `*.pre-<migração>.bak` antes de migrar um banco existente.
- Posições com inteiros esparsos e renumeração; `revision` por cartão dá bloqueio otimista (409 em aba velha).
- Validação em pt-BR com `ValidationError`, texto limpo de caracteres invisíveis (`clampText`).
- Export/import versionado (`snapshot.go`), compatível com o export da v0.4.0-alpha.1.
- 698 linhas de teste cobrindo CRUD, posições, WIP, filtros, snapshot e erros `ErrNotFound`.

## Markdown (internal/markdown)

Renderizador próprio só com stdlib: escapa todo HTML, aceita título, ênfase, código, listas, checklist, citação e links `http(s)`/`mailto`; devolve `template.HTML` apenas da própria saída. Contagem de checklist para o cartão. Sem achados.

## Desktop (desktop/)

Electron 44: sobe o binário Go como sidecar com `--addr 127.0.0.1:0 --db <userData>/kanban.db`, espera a linha `LISTENING host:port` no stdout, grava stderr em `logs/kanban.log` (rotação em 5 MB), instância única, estado da janela persistido, encerra o sidecar ao sair. O contrato (flags, linha `LISTENING`, `/healthz`) é usado também por `scripts/e2e-server.ts` e `scripts/smoke.ts`.

## Bugs e achados

- [ ] **Teste (corrigido na migração):** `TestOpensDatabaseFromV040Alpha1` lê `testdata/v0.4.0-alpha.1.db`, mas `*.db` está no `.gitignore` e o arquivo nunca foi versionado; em clone limpo o teste falha. Corrigido gerando o banco legado dentro do teste.
- [ ] **go.mod:** `modernc.org/sqlite` aparece como `// indirect` embora seja importado diretamente; `go mod tidy -diff` não é vazio. Resolvido pela migração (o `go mod tidy` regenera o arquivo).
- [ ] **Processo:** `AGENTS.md` proibia criar `.github/workflows/`; não havia CI nem checagem automática de Conventional Commits. Resolvido com `.github/workflows/ci.yml`.
- [ ] **Divergência de dependência:** `AGENTS.md` dizia que a única dependência Go de runtime era `modernc.org/sqlite`; a migração adiciona `github.com/AlexGalhardo/vukem` (decisão do dono, tarefa 3.b do ROADMAP).
- Sem achados de segurança: SQL sempre parametrizado, markdown escapado, CSP sem `unsafe-inline`, CSRF por `Sec-Fetch-Site`/`Origin`.

- [ ] **Dependências JS:** `bun audit` reporta 8 advisories altos: `electron` 44.5.1 (GHSA-jr5w-w6x2-84p9, corrigido na 44.9.1) e `undici` transitivo (sete avisos). Atualizar o Electron exige aprovação do dono; o CI barra só `critical` até lá.

## Migração para o vukem

Resultado (mesmo dia, branch `feat/migrate-to-vukem`):

- Estrutura de app vukem v0.43.0: `bootstrap/`, `routes/`, `app/controllers/`, `database/migrations/`, `resources/`, `tests/`. As 860 linhas de handlers viraram `func(*web.Ctx) error` sobre o `store` existente; o `store` e o `markdown` não mudaram de comportamento.
- Views: todos os templates viraram blocos de `resources/views/partials/` renderizados pela página-host `kanban` (`layout: none`) com `Views.RenderBlock`; o engine do vukem não precisou de mudanças no HTML.
- Middleware: stack padrão do vukem em modo `Stateless` (sem sessões), `BodyLimit` de 1 MiB (20 MiB no import), CSP com nonce e `no-referrer`.
- Migrações: SQL embutido rodando no migrator do vukem; bancos do runner antigo (`schema_migrations`) são reconhecidos e nenhum dado é perdido (teste `TestOpensDatabaseFromV040Alpha1`).
- Contrato do desktop preservado: `--addr`, `--db`, `--log-level`, `--version`, linha `LISTENING`, `/healthz`.
- Validação final: `gofmt -l .` vazio, `go vet ./...`, `golangci-lint run ./...` (0 issues), `go test -race ./...`, `bun run smoke` (8 checks), `bun run e2e` (50 passed) e `bun run e2e:desktop` (4 passed).

Pendências e diferenças conhecidas:

- Os testes Go do app agora vivem em `tests/` (pacote externo ao `controllers`); `TestPanicRecovery` foi removido porque recuperação de panic e log de requisição passaram a ser do framework.
- O log de requisição mudou de formato (`duration` em vez de `duration_ms`).
- `APP_ENV` assume `production` e `APP_KEY` é gerada por processo em `cmd/kanban`: o vukem exige a chave mesmo sem sessões.
